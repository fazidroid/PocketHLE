исправления игры (Windows Mobile)

Репозиторий: https://github.com/j92580498-max/PocketHLE

## Задача
Ты работаешь с игрой для платформы:
- Windows Mobile 

Проблема: приложение не запускается / не работает. Нужно найти причину, исправить код так, чтобы игра доходила до игрового процесса и все элементы (интерфейс, объекты, экраны) корректно отображались.

## Что нужно сделать

1. Проанализировать проект
   - Изучить структуру репозитория, точку входа приложения, используемые SDK для Windows Mobile.
   - Найти, на каком этапе происходит сбой запуска (инициализация окна, загрузка ресурсов, работа с памятью и т.д.).
   - Диагностический признак: если в логах значение frame_counter=0 (не увеличивается) — игра не работает и ничего не отображается. Нужно найти, почему frame_counter не инкрементируется, и исправить эту часть кода (главный цикл, отрисовка кадров, обновление счётчика).

2. Использовать документацию
   - Найти и изучить актуальную документацию по разработке под Windows Mobile (MSDN-архивы, Microsoft Docs, форумы разработчиков той эпохи).

3. Использовать глобальный поиск по GitHub
   - Через глобальный поиск кода на GitHub найти open-source проекты для Windows Mobile, где встречаются аналогичные функции/структуры (инициализация экрана, работа с ресурсами и т.п.).
   - Сравнить найденные рабочие реализации с текущим кодом проекта и использовать их как референс для исправления багов.

4. Исправить код
   - Устранить причину, из-за которой игра не запускается.
   - Добиться того, чтобы приложение доходило до игрового экрана.
   - Проверить, что все графические элементы, спрайты, интерфейс отображаются корректно.

5. Протестировать с помощью tools/ai-tap-sequence.py
   - Использовать скрипт tools/ai-tap-sequence.py из репозитория для автоматизированного тестирования игры (выполнение последовательности тапов/действий, проверка реакции интерфейса).
   - Прогнать тестовый сценарий на эмуляторе или устройстве, убедиться, что игра корректно реагирует на все шаги сценария и не падает.
   - Если скрипт выявляет ошибки — вернуться к шагу 4 и доработать код.

6. Предоставить доказательство исправления
   - Запустить исправленную версию в эмуляторе или на реальном устройстве.
   - Сделать скриншоты, подтверждающие, что игра дошла до игрового процесса и все элементы отображаются корректно.
   - Приложить результаты прогона tools/ai-tap-sequence.py (лог/вывод скрипта) как дополнительное доказательство.
   - Без скриншотов и результатов тестового скрипта исправление не считается подтверждённым.

7. Зафиксировать изменения через Pull Request
   - Создать отдельную ветку от main.
   - Закоммитить изменения в эту ветку.
   - Открыть Pull Request в репозиторий:
     https://github.com/j92580498-max/PocketHLE
   - В описании PR кратко указать: что было исправлено, почему, как проверено (включая вывод tools/ai-tap-sequence.py).
   - Приложить скриншоты-доказательства и результаты тестирования непосредственно в описание PR (или как вложения/комментарии к нему).
   - Не делать прямой push в целевую ветку — все изменения должны проходить через PR.

## Критерий готовности
Игра успешно запускается на Windows Mobile, доходит до игрового процесса, все элементы отображаются без ошибок, тестовый сценарий tools/ai-tap-sequence.py проходит без сбоев, изменения оформлены в виде Pull Request со скриншотами и результатами тестирования.
